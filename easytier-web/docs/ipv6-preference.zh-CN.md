# IPv6 优先（可选）

`prefer_ipv6` 默认关闭，旧配置保持原行为。启用后优先尝试可用的 IPv6 底层连接，保留 IPv4 回退；VPN 内部使用 IPv4 地址也能通过 IPv6 隧道传输。

## 配置

CLI：`easytier-core --prefer-ipv6`；显式关闭：`--prefer-ipv6 false`。环境变量：`ET_PREFER_IPV6=true`。

TOML 在相应实例的 flags 中设置：

```toml
[flags]
prefer_ipv6 = true
```

单文件多实例配置则使用相应实例的 `[instances.flags]`，每个实例独立设置。

中央 Web：网络详情 → 设置 → IPv6 优先。成员高级配置提供三种状态：

- **跟随网络**：不保存成员级 `prefer_ipv6` 覆盖；编辑 MTU 等其他选项仍保留继承，今后修改网络默认值也会生效。
- **优先 IPv6**：保存成员级 `prefer_ipv6=true`，覆盖网络默认值。
- **默认选路**：保存成员级 `prefer_ipv6=false`，按原有连接策略选路，不表示禁用 IPv6。

从显式设置切回“跟随网络”会移除该项覆盖。普通桌面、Android GUI 和独立 Core 使用布尔开关，默认关闭；中央网络的成员配置才使用以上三态。旧 Core 不支持该选项时会忽略，新客户端发布与实机验证范围以对应版本的验证记录为准。

禁用 IPv6 时，该偏好不会重新启用 IPv6。只有 IPv4 的对端立即使用 IPv4，各对端分别选择地址族。

## 连接行为

IPv6 获得 250 毫秒的尝试时间，快速失败立即开始 IPv4；IPv6 暂无响应时会启动 IPv4 回退。已建立的 IPv4 可继续承载流量，同时允许有界的 IPv6 尝试完成。启用时，同一域名的多个 IPv6 地址共享连接预算并发尝试。

只有通过存活验证的 IPv6 连接会成为首选。IPv6 断开后使用仍存活的 IPv4；已有可用 IPv4 时，P2P 的 IPv6 再尝试有 60 秒冷却时间，避免不稳定链路频繁切换。两族都断开时不因冷却延迟重新连接。禁用 P2P 的纯手动入口只在初次连接或连接全部断开时重试；已有 IPv4 时，不会周期重拨同一入口来升级 IPv6。

## 入口和客户端

IP 字面量只提供对应地址族。要让初始 Gateway 连接也能选择 IPv6 并回退 IPv4，应使用指向真实 VPN 服务器的 A/AAAA 双栈域名；不要使用仅代理 HTTP 控制台的 CDN 域名。Gateway 公开地址现在作为 mapped listener 广告给成员，不额外绑定端口。

客户端 Core 需要包含此功能。旧客户端继续兼容基础组网，但不会执行 IPv6 优先；控制器会显示升级提示，避免反复重建旧实例。旧 API 更新网络时省略这个字段会保留原设置，显式 false 才会关闭。

## 成员与凭据

从网络 A 移除成员只撤销 A 的成员资格、专属网络凭据和托管配置。设备的管理接入令牌、设备记录及网络 B 的成员身份保留，设备可以继续加入其他网络。删除设备或主动撤销管理令牌属于单独操作。
