# 中央组网的双栈连接

管理连接和节点间的数据连接分别选路。节点通过 IPv4 连接配置服务器后，仍应发现并尝试对端的 IPv6 端点。每一对节点独立决定地址族，IPv4 节点不改变其他节点对的 IPv6 优先级。

## 配置与端点

- 控制器编译成员配置时继承网络的 `prefer_ipv6`，保留成员的明确覆盖。
- 启用 P2P 且没有显式监听端点时，配置 `udp://0.0.0.0:0`。操作系统为每个实例分配端口；启用 IPv6 时 Core 增加 IPv6 监听，并上报实际绑定的非零端口。
- 手动指定的监听端点保持原值。`disable_p2p` 和 `disable_ipv6` 分别控制 P2P 及 IPv6。
- 端点发现使用节点间的 `GetIpList` RPC，合并运行中的监听端点、接口地址及 STUN 反射地址。管理连接的地址族不限制这些结果。
- 网关的跨网络 RPC 保持只广告明确映射的监听端点，并关联同实例的实际监听器来处理反向打洞控制。
- 中央 Web 为多个网关实例共享 UDP socket。只有 Web 成功绑定后的实际端点才授权给网关的反向打洞控制；该授权随监听任务退出或取消撤销。共享端点不进入实例自己的监听广告，跨网络 RPC 仍只返回明确映射的端点。
- IPv6 STUN 成功的结果独立发布，不要求 IPv4 NAT 探测先成功，并更新探测时间。

## 建链与回退

IPv6 优先是每对节点的连接策略。IPv4 已经连接时仍应尝试 IPv6；IPv6 确认可用后才优先使用该连接。IPv6 探测失败时保留可用的 IPv4 或中转连接，后续继续尝试。

IPv6 UDP 反向打洞应使用即将建隧道的同一个 socket 查询完整反射端点，包括公网地址和端口。不能假设 NAT 始终保留 UDP 端口。反射查询有时间上限，失败时仍可尝试原生公网 IPv6 候选，不无限阻塞回退。

UDP 建链确认通过连接标识及随机校验值关联响应，可以接受实际来源地址与候选不同的有效响应。不能将没有这些关联信息的普通打洞包扩展为接受任意来源。

静态映射的外部端口与实际本地监听端口需要分开处理。反向打洞控制优先匹配同地址族的实际 UDP 监听端口；外部端口没有本地匹配时，必须先确认它属于已配置的映射广告，再选择实际本地监听端口。无法确认的映射不能用于猜测本地控制端口。

域名形式的映射只解析已配置且端口匹配的 UDP 广告，使用请求的地址族及实例的 DNS 上下文，总等待最多一秒。解析成功后再次确认映射和实际监听所有者仍然存在；实际端口已匹配、未知端口或没有监听所有者时不查询 DNS。

## 配置更新

控制器启动及周期调和会重新编译已有网络意图。期望配置有变化时更新配置修订并通知客户端；端口 `0` 保留在期望配置中，实际随机绑定端口只进入运行状态，避免每次调和产生新的修订。

监听端点修复不改变成员、凭据、网络标识、虚拟地址分配及成员覆盖配置。

## 可达性边界

绑定本地端口不等于证明该端口从公网可达。连接端 socket 的 STUN 结果也不等于所有目的地都使用同一出口。多出口策略路由可能让节点向 STUN 和对端分别使用不同公网 IPv6；NPT、PAT、防火墙及上游网络需要实际双向 UDP 和隧道验证。

因此验收需要区分本地监听、公布的候选、实际包头及成功建立的连接。不能只凭设置 `prefer_ipv6` 或显示公网 IPv6 就判定 IPv6 隧道已经成立。

## GUI 数据契约

Rust 的 protobuf JSON 可能省略默认标量、空数组和不存在的可选消息。GUI 在 IPC 边界恢复数组及标量默认值，不伪造可选消息。

路由的空 `proxy_cidrs` 是合法结果。网络元数据的 `config_permission = 0` 表示允许用户管理自身配置，省略这个标量不能被解释为只读；元数据消息整体缺失时仍应禁止修改。
