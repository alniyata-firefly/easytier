# 管理网页日志

侧栏“日志”提供两个入口：管理员可查看“服务端日志”，所有登录用户可查看自己账户的“设备连接日志”。服务端权限来自当前用户在数据库中的 `admins` 组，每次查询都会重新校验；用户名或采集令牌不授予此权限。

服务端日志从 Web 服务启动时开始采集，独立于控制台、文件日志及 `RUST_LOG` 的级别设置。保留当前进程最近 2000 条 INFO/WARN/ERROR 事件，超过后淘汰最早记录，重启后清空。页面显示启动时间、容量和淘汰数量，检测到进程变更会重置分页。

页面支持最低级别、模块前缀和消息/字段搜索，最新页默认每 5 秒刷新，可暂停。查看较早记录时暂停自动刷新。导出功能下载当前筛选页的 JSON，包含查询条件和进程信息。

采集内容是管理服务的安全诊断摘要，包括启动、管理连接、认证、配置操作和异常。只保留审核过的消息及有限的标识符、计数、布尔字段；动态错误详情、完整配置、令牌、网络密钥和内嵌 Core 的原始日志不会写入网页缓冲。未知消息以固定摘要标记。它不读取系统 journal 或历史日志文件。

`GET /api/v1/server/logs` 需要管理员会话，响应 `Cache-Control: no-store`。参数：

| 参数 | 取值 |
| --- | --- |
| `level` | `INFO`、`WARN`、`ERROR`，表示最低级别 |
| `target` | 最长 128 字符的模块前缀 |
| `q` | 最长 128 字符的搜索文本 |
| `before_id` | 正的安全整数，查询更早记录 |
| `limit` | 1–200，默认 50 |

返回 `entries`、`next_before_id`、`instance_id`、`started_at`、`capacity`、`dropped_entries`、`oldest_id` 和 `newest_id`。事件时间和启动时间使用 Unix 毫秒。连接日志继续使用原有按账户持久化的管理事件接口，不受服务端内存缓冲重启影响。

CI 在 `Source checks` 手动工作流设置 `server_logs_only=true`，运行日志采集、权限和网页回归，随后只构建 Linux x86_64 Web 服务端及网页。实际预编译服务测试会关闭普通日志输出，检查启动事件、查询、权限撤销、敏感数据排除和重启行为；不会启动托管 Core 或访问生产服务。
